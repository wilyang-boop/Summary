VIP System Overview
Vehicle Integration Package · Release Baseline Architecture
VIP (Vehicle Integration Package) is the validated release baseline for a vehicle program — a compatibility contract binding software, firmware, coding, and configuration into a single fleet-usable package.

NDAS — driving/application stack
The main driving and application stack. Sits at the top of the software hierarchy — it calls AA's platform services to do its work. NDAS-only bundles may fail the pipeline, so it always moves as part of a full VIP/DDU update.

AA — Adaptive AUTOSAR
AA — Adaptive AUTOSAR stack
Middleware/platform services layer. Runs QNX user-space (X6*) processes. Sits between AVOS and NDAS and:
  • Talks to radars, subscribes to sensor data
  • Manages SC7 suspend/resume power state
  • Coordinates with LCM, FSI, MCU/Aurix
  • Exposes platform services NDAS depends on
If X6* processes are missing, AA is down — flash an LKG DDU. AA persistence must match its DDU version.

FSI — versioned SW component
Another versioned software component shipped in the same DDU baseline, managed as part of compatibility control alongside AVOS, AA, and NDAS.

DDU
DDU — Direct Drive Update
The flashable tarball put on the IDC/Orin during the SW update step.
  • QNX / AVOS platform image
  • AA adaptive binaries
  • NDAS build
  • FSI and low-level components
  • DDU_build_info.txt (crypto-type detection)
DDU = the main software image bundle for the IDC
 bundles NDAS + AA + AVOS/QNX + FSI as one flashable image
IDC SW depends on compatible firmware below
Aurix MCU
Aurix — MCU firmware
Separate MCU/control-side firmware domain. Even with a correct DDU, a mismatched Aurix version can break provisioning, boot, or vehicle integration — hence its own explicit flashing step in every VIP.
Bad Aurix releases can break clear-persistency or SW update entirely.
MCU firmware · separate domain
Switch
Switch — network switch firmware
In-vehicle network switch firmware. Tracked separately from the DDU and flashed alongside Aurix as its own VIP step. Radar
Radar — sensor firmware
Sensor firmware outside the DDU. AA subscribes to radar data — mismatches break that integration even when the IDC software is correct. Gateway
Gateway — vehicle network firmware
Vehicle-network / communication firmware. Mismatches can break provisioning or inter-ECU communication even when the IDC baseline is correct.

Why Aurix churns
Aurix is a separate compatibility axis — bad releases break clear-persistency or flashing, forcing a full package refresh even when the feature story hasn't changed.
NDAS needs VIP upgrade
NDAS-only bundles may fail the pipeline. NDAS sits above AA inside the DDU — moving it safely means moving the whole validated Vehicle Integration Package.
